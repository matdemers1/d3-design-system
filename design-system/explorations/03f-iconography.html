3f — Iconography

One library, four sizes, a stroke that stays put, and the fix for the colour-only priority dot.

Four apps, four answers again: Bindery imports 49 icons from Lucide, App A imports 27 from @mui/icons-material, App B hand-rolls 19 inline SVGs across two different viewBoxes, and App C has no icons at all — not a library, not an SVG, nothing. This picks Bindery's answer, because it is already proven in the codebase and because all 27 of App A's MUI icons map one-to-one onto it.

The library

Lucide ISC · 2,022 icons · v1.35.0 · tree-shakeable

Already vendored in Bindery and used for 49 icons across 36 files, so it is a known quantity rather than a bet. Drawn on a 24×24 grid with consistent joins and caps, which is what makes a stroke rule possible at all. All 27 of App A's MUI icons have a direct Lucide equivalent — the table below is the migration, and it removes @mui/icons-material along with MUI itself (D-010).

Stroke-width is a function of size, not a constant. Lucide defaults to 2 in a 24px viewBox, so an icon rendered at 11px draws a 0.92px stroke — under one device pixel, which blurs on any 1× display. Bindery renders icons at eight sizes (11, 12, 13, 14, 15, 16, 19, 44) all at the default stroke, so its icon weight varies by 45% across a single screen. The four sizes above pair each with a stroke that keeps the rendered line inside a 1.17–1.50px band, so a 14px icon and a 24px icon look like they came from the same family.

Optical alignment Inter's cap-height measures 0.7275em — icons align to it, not to the em box

12px metadata + 14px iconExport fails silentlycap 8.7px · icon 14px
14px body + 16px iconExport fails silentlycap 10.2px · icon 16px
16px emphasis + 20px iconExport fails silentlycap 11.6px · icon 20px
20px section title + 24px iconExport fails silentlycap 14.6px · icon 24px
The icon box is always one step larger than the text size — 14px text takes a 16px icon. That looks wrong written down and correct on screen: a stroke glyph reads lighter than a letterform of the same height, so matching the em box makes the icon look shrunken. Matching roughly cap-height + a little is what makes them feel equal. Alignment is display:inline-flex; align-items:center — never a hand-tuned vertical-align or a magic margin-top, which is what breaks the moment someone changes the line-height.

When an icon may stand alone

Icon-only is allowed

  • The action is non-destructive and reversible
  • It sits in a persistent location the user can learn — a toolbar, a row, a header
  • It has an aria-label — always, no exceptions
  • It has a tooltip on hover and on keyboard focus
  • It is one of a small set used the same way everywhere: close, search, expand, more, edit

Icon-only is not allowed

  • Anything destructive. Delete, dismiss, revoke, purge — these carry a word
  • Anything that spends money or sends something to another person
  • Anything appearing fewer than a handful of times, where there is nothing to learn
  • The primary action of a page or a dialog
  • Anywhere the icon is the only signal of a state — see the priority dot above

Icons that move three, and no more

disclosure — rotates 180°, 200ms loading — 1s linear, the one place linear is correct confirmation — draws once, never loops in production
Motion is expressive (D-024), but icons are not where that budget goes. Three animations exist: a disclosure chevron rotating, a loading spinner, and a confirmation check drawing itself once. Everything else — hover states, nav icons, status glyphs — is static. An icon that animates for decoration competes with the layer animations that are carrying real meaning, and in a table of forty rows it is simply noise.

Custom icons

A custom icon is drawn only when Lucide genuinely has no equivalent — the D3 Cloud mark itself, and Bindery's document-type glyphs are the likely cases. When one is drawn it uses the same constraints as the library, so it does not read as a guest: 24×24 viewBox, stroke-based, round caps and joins, 2-unit nominal stroke, no fills except where the shape is the meaning (as with the priority marks above). A custom icon that ignores the grid is obvious at 14px next to one that does not.
